# Content in the public source edition

The planner uses canonical work and unit identifiers. It can run with a small content index supplied by the caller. The examples use invented plans, dates, work descriptions and counts. Their tasks demonstrate the scheduling rules without copying a published edition.

| Material | Public distribution |
| --- | --- |
| Masoon source, build descriptions, documentation and original example fixtures | Included under the [repository license](../../LICENSE), subject to [third-party notices](../../THIRD_PARTY_NOTICES.md). |
| Qurʾān editions, page and glyph maps, QCF fonts, rendered headers, and combined edition-specific indexes | Omitted, including generated copies, golden outputs from those datasets and native resource bundles. |
| Tafsir, translations, adhkar transcriptions, reading packs, poetry collections, and published curricula | Omitted. Rules, schema field names and user-interface terminology can refer to these content types. |
| Reciter recordings, timing packages, recitation models, model weights and reference audio | Omitted. |
| Official icons, store artwork, screenshots, signing material, account configuration and deployment records | Omitted. The UI examples use locally rendered controls and synthetic inputs. |
| Third-party development libraries | Where used, dependency declarations refer to upstream packages. Review their licenses for the version and artifacts you distribute. |

To add a content pack, document each source and edition, the rights holder, permission for the intended use, and any required notices. Check permission for raw-source redistribution, modifications and binary bundling separately. A downloadable file or public API endpoint alone does not establish those permissions. Keep the source, the generated copies and their attribution together.
